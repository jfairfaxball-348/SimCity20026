## Implemented contract

Decisions D19–D21 and the M2b power rule were written in [Decisions](../DECISIONS.md) before model code. Summary:

- **Source:** one single-tile power station, provisional $500, 20 power units, no upkeep/fuel/access requirement. One station per command; a multi-tile stroke is rejected before any charge. It cannot be placed on the outside-link marker. Clear is free with no refund.
- **Demand:** each home-zone plot requests 1 unit. Nothing grows.
- **Networks:** road and station tiles joined by shared sides. Stations relay power like roads; diagonals, homes, open land, and water do not. Network capacity = stations × 20.
- **Independence:** a station powers its own network with or without the outside link. Stations do not relay road access or count as roads beside homes. The inspector shows road access and power as separate lines.
- **Allocation:** nearest first. Plots touching a sourced network are served in (station distance, row-major plot index) order. Each draws from its touching network with room that has the smallest (distance, network order). There is no stored allocation history.
- **Explanations:** powered (with network use and any shortfall), capacity shortage, disconnected, no road/station beside the plot, no station built yet. Roads/stations report network use; the toolbar shows used/capacity and plots short.

`game/scripts/sim/power_grid.gd` is scene-independent and derived. `CityState.rebuild_derived()` rebuilds access and power at initialization, validated load, and after every successful occupancy-changing command. Previews, rejected/no-op commands, and ticks never change it. Labelling, multi-source distance search, and allocation are iterative with a fixed neighbour order. Power is never serialized and consumes no RNG.

The UI adds the P tool, an original station glyph, E power marks (bolt powered / cross unpowered, distinct shapes as well as colours), Road [R] / Power [E] toggles in one row, a toolbar power total, an inspector power line, help/README text, and a migration status message. The scope line now reads "Growth not implemented; plots stay empty."

## Save versioning and migration

- Schema **2**, simulation/content **m2b-1**; occupancy ID **3** = power station; IDs 0–2 unchanged. Game version is separate.
- Schema-1 saves (`m1-1`, IDs 0–2 only) are validated, then migrated in memory by changing only the three version fields. Loading never writes.
- Before a save replaces a valid schema-1 primary, or rotates over a valid schema-1 `.bak`, it copies that file's exact bytes to `manual.schema1.json` (never overwriting an existing copy), then rotates `.bak` as before. If the copy fails, nothing is replaced.
- Rejected without changes: schema > 2 ("made by a newer version"), schema 2 with `m1-1` strings, schema 1 with `m2b-1` strings, schema 1 containing ID 3, a station on water, unknown IDs.
- Build 0.2.0 already rejects schema 2 through its own schema check. Rolling back requires the preserved schema-1 copy.

Before any model edit, the **unchanged M2a code** generated `game/tests/fixtures/m2a-schema1.json` (SHA256 `a85895efbc23707538a8c97399a7cf9bd831bfeb21b8182144b68653d82f0c93`) and printed its derived access: root `(9,4)`, 6 connected roads, 4 served homes, and reasons for all seven homes. Tests assert that these results survive migration. The M1 fixture's bytes (`f954b5c7…`) are also hash-checked. The final M2b code then wrote `m2b-schema2.json` (`27dbbaef…`) as a schema-2 sample for any future migration. See the [fixture README](../../game/tests/fixtures/README.md).

## Corrections found during verification

- At text 20 the inspector needed 337 px against a 320 px cap. Shortening the scope sentence brought the minimum to 306 px. A text-size change could still leave a transient, never-shrinking panel that reached the footer. The inspector now re-fits to its target rectangle on each refresh. Height stays at 320 px so the centred flag is never covered, and it is wider at larger text.
- A packed step was blocked because an earlier corrupt-load check correctly opens the backup-recovery dialog. The driver now asserts that dialog and closes it.
- Packed pointer strokes on row 33 east of x≈52 would land under the 720p inspector. A station mid-street also (correctly) breaks road access. The flow keeps stations at street ends west of the inspector.
- The nearest-first test gap and the PowerShell 5.1 issues described above.
- Diff review found that preservation only covered a schema-1 **primary**. After recovering from a schema-1 `.bak` over a corrupt primary, a later rotation would have dropped the old-format bytes while the status line promised to keep them. The store now also preserves a schema-1 backup before rotating over it, with tests and a native recovery run. The `.bak` status message now says this.
- The native driver's first final-build run crashed on a GDI handle type (ctypes default int) after capturing; the game and save files were unaffected. The driver was fixed and the step re-run.
