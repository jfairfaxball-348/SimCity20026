# M2c growth: implementation and local evidence

Dates: **4-5 November 2026**. Version **0.4.0-m2c**. **Implemented and tested locally; not a public game release.** M2d remains unimplemented. The owner authorised growth, Windows-export testing, documentation, commit, push, and merge into the default branch.

## Scope and design

The clean baseline was `c18cf6f` on default branch `codex/m2a-road-access`; work used `codex/m2c-growth`. The unchanged baseline passed **233 source / 252 packed checks**. D22-D24 were recorded in [Decisions](../DECISIONS.md) before model edits.

M2c adds home/shop/workshop levels 0-2, aggregate population/jobs/demand, five-day growth rounds, and service-loss decline/recovery. Zones cost $25 and use one power unit even empty. Home levels hold 4 residents; shop/workshop levels provide 2/4 jobs. Prior-state home target is `min(2*cells,3+floor(jobs/2))`; both business targets are `ceil(population/16)`. Three starter home levels break the empty-town deadlock. Each round reserves at most eight additions per type, one per eligible plot, row-major, then applies all changes together. Demand satisfaction alone never evicts buildings.

Growth needs road access and allocated power. A developed plot loses one level on every second consecutive growth check without both. Restoration immediately resets its loss counter; normal demand permits recovery. Nearest-first power remains derived, including new empty plots displacing grown ones. Ticks do not change allocation, cash, command sequence, or RNG.

The UI adds keys 6/7, residents/jobs/demand, development and growth explanations, and original line/rectangle building silhouettes. Display/Help share a row; Help text was shortened to fit 720p at largest text. No economy, park, nuisance, project, audio, controller, autosave, external asset/dependency, licence grant, purchase, or public release was added.
